## 1. 反馈一：6 弦、1 弦空弹捕捉不敏感

### 1.1 诊断（先测量，不猜）

用用户同一支麦克风的录音（`录音3.m4a`，六根空弦各 3 次）逐级统计：

```
分析配置：window=2048 hop=480 low_enhance=True low_window=8192 mode=auto
门限：-60dB + 12dB = -48dB

  弦            有效帧   中位频率     置信度   电平(dB)
  第6弦 E2          243      81.62Hz   0.961     -37.0
  第5弦 A2          209     109.49Hz   0.956     -37.3
  第4弦 D3          201     145.75Hz   0.993     -29.6
  第3弦 G3          207     196.08Hz   0.992     -32.2
  第2弦 B2          192     246.30Hz   0.992     -31.4
  第1弦 E4          197     329.31Hz   0.995     -31.0
```

**六根弦的检测全部正常**，置信度 0.95+。所以问题不在音高检测，而在**判定流程**。
进一步复现出两个机制性问题。

### 1.2 问题 A：宽容期把正确答案也压住了

默认宽容期 2.0s，期内**完全不判定**（旧代码在计算读数之前就 `return None`）。
弹空弦不用按品，用户看到题立刻拨响 → 这一下被静默忽略整整 2 秒。

宽容期的本意（需求 FR-535）是"试音不判错"，**不是压住正确答案**。

修复：

- **宽容期内弹对立即算对**（`_decide(correct_only=True)` 只放行"判对"）；
- 判错仍然留到宽容期之后 → 试音保护不变；
- 宽容期结束的那一刻清一次滑动窗口，确保期内弹错的音不会在期后被当成答案判错。

实测：宽容期内弹对从"等到 2 秒后"变成 **540ms 内算对**。

### 1.3 问题 B：琴弦余振中重拨会漏检起音

原起音判据只看"相对最近 3 帧最大值的突跳（≥8dB）"。琴弦还在响时，最近几帧电平
本来就不低，重拨带来的增幅常常不到 8dB → **漏检起音** → 判定器一直处于"未武装"
状态 → 用户怎么弹都没反应。用户弹空弦（不用按品）时经常连续快速拨弦，正是这种情况。

修复：新增第二条判据 —— 相对最近 150ms **谷底**回升 ≥6dB。

- 衰减中的琴弦在最近若干帧里是单调下降的，"最近 150ms 的最小值"就是最新的一帧，
  重拨会让电平明显回升 → 被抓住；
- 但单纯加这条会带来一个**副作用**（实测发现）：缓冲区刚填满时会因为"初始静音"而
  延迟误报一次起音。因此再加一条约束：**必须相对上一帧在上升**（≥3dB）。
  纯衰减过程电平在下降 → 被排除；稳定音最小值≈最大值 → 不会触发。

### 1.4 界面与设置

- 宽容期内显示"**试音中 x.x s**"（蓝色进度条）。此前用户拨了毫无反馈，
  这是"不敏感"感受的重要来源 —— 现在明确告诉他"听到了，只是还没计入判定"。
- 会话设置对话框新增「宽容期」0~5 秒可调（FR-534 允许 0~5s），
  并说明"弹对了会立即算对、0 表示立即判定"。
- 宽容期与超时一样改由**会话配置**决定（用户策略），不再取模块的判定配置。
  这一改动让三个原有测试暴露出来（它们依赖旧的短 grace），已同步修正。

## 2. 反馈二：用户账号与吉他档案

### 2.1 学习者账号

`profiles` 表与增删改在 M1 就有了，缺的是界面与切换逻辑。新增「账号与档案」菜单 →
`ProfileManagerDialog`：

- 学习者账号页：新建 / 重命名 / 删除 / 设为当前，当前账号用 `●` 标记；
  只剩一个账号时禁用删除；删当前账号时自动切到剩下的；
- 补上 `last_profile_id` 的记忆（原先只在启动时读，切换后不写回）；
- 切换后同步设置访问器、首页、统计页。

**账号隔离是这项功能的实质**，因此测试重点放在隔离上：设置按账号分开、训练项互不可见、
统计互不影响，而全局设置（语言/设备/乐器档案）保持共享。

### 2.2 吉他档案

`data/instruments/` 下的档案此前只能用菜单逐个选，新增管理能力：

- 列表（标注是否已实测）、测量新建、设为当前、重命名、删除、查看；
- 文件层新增 `list_saved_profiles / rename_saved_profile / delete_saved_profile`；
  **坏文件跳过**而不是让整个列表失败；重命名会同时改 `name` 与文件名，保持两者一致。

## 3. 顺带修掉：自检不退出，锁住数据库导致打包失败

打包时出现：

```
PermissionError: [WinError 32] 另一个程序正在使用此文件:
D:\JitaTrainer\dist\JitaTrainer\data\jitatrainer.db
```

排查发现**上一次打包的自检进程仍然活着**（16:30 启动），占着数据库。
根因是 PortAudio 在 Windows 上可能留下原生线程把进程吊住 —— 自检打完了却不退出。

这类问题会让下一次构建偶发失败，必须治本：自检入口在写完报告、关掉窗口后改用
`os._exit()` 强制退出（先 flush 输出）。自检是一次性冒烟入口，没有需要优雅收尾的资源；
正常 GUI 启动路径不受影响。

修复后实际重跑打包：产物自检退出码 0，且**不再残留进程**。
