## 1. 本机环境的三个硬约束（全部实测确认）

M1 最耗时的部分不是写功能，而是把本机环境的三个"陷阱"查清楚并做成兼容层。
这些结论对后续所有里程碑都有效。

### 1.1 `os.mkdir(path, 0o700)` 创建的目录不可写

| 创建方式 | 结果 |
|---|---|
| `os.mkdir(path, 0o700)` | ❌ ACL 损坏，**连 `icacls` 都无法处理**，读写全部被拒 |
| `tempfile.mkdtemp()`（内部用 0o700） | ❌ 同上 |
| `os.mkdir(path, 0o755)` / `0o777` | ✅ 正常 |

**影响**：pip 无法安装任何包（内部用 mkdtemp 解包）；pytest 的 basetemp/编号
临时目录机制（`make_numbered_dir(mode=0o700)`）会让整个测试会话在清理阶段崩溃。

**对策**：
- 依赖改为**解包官方 wheel 到 `.vendor/`**（`run.py` / `conftest.py` 负责加入 `sys.path`）；
- `src/jitatrainer/compat.py` 在运行期探测并修补 `tempfile.mkdtemp`；
- `conftest.py` **接管 pytest 的 `tmp_path` 夹具**，把临时目录固定到工作区内的
  `.tmp/tests/`，完全绕开 pytest 的临时目录回收逻辑。

> 说明：`.tmp/pytest` 与 `.tmp/pytest-work` 两个目录在首次崩溃时被写坏，
> 后续 `takeown` / `icacls` / `Remove-Item` 均无法清除，只能留在本地
> （已被 `.gitignore` 排除，不影响仓库与运行）。

### 1.2 pip 的失败链条（供日后排查参考）

```
pip install sounddevice
  → normal site-packages is not writeable（沙箱只允许写工作区）
  → Defaulting to user installation
  → mkdtemp 解包 → PermissionError: ...whl.metadata
```

### 1.3 PowerShell 的 schannel TLS 不可用

`curl` / `Invoke-RestMethod` 访问 GitHub 报
`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`，
而 Python 自带 OpenSSL 正常、git 也正常。因此所有 HTTP 调用统一走 Python。

## 2. 交付内容

### 2.1 代码结构（与技术方案 §3.3 一致）

```
src/jitatrainer/
├─ app.py                    入口 + 主窗口 + 离屏自检
├─ compat.py                 环境兼容层（mkdtemp 修补）
├─ paths.py                  绿色版路径解析（数据存程序目录）
├─ core/theory/              notes / tuning / levels / fretboard
├─ core/audio/               pitch_yin / ring / events / device
├─ core/judge/               base / pitch_class_judge
├─ data/                     db.py + migrations/v001_initial.py
└─ i18n/                     __init__.py + zh_CN.json + en_US.json
```

### 2.2 判定引擎（M0 实测结论的落地）

- 滑动窗口 + 多数表决（**不是**连续帧全合格）
- 三档稳定时长预设：快速 150ms / **平衡 200ms（默认）** / 稳健 300ms + 高级自定义
- 三种试音模式：宽容期（默认）/ 严格 / 宽容（不判错）
- 单帧置信度下限 0.80；容差默认 ±25 音分
- 答错停留直到弹对，尝试次数逐个计入

### 2.3 数据层

SQLite（WAL）+ 版本化迁移 + 自动备份。迁移用 Python 模块而非独立 `.sql` 文件，
避免 PyInstaller 收不到数据文件。备份文件名含毫秒并带序号兜底。

## 3. 测试抓出的三个真 bug

单元测试不是走过场，本轮抓到的问题都会造成实际故障：

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | `PitchEvent` 缺少判定层要用的 `pitch_class` 属性 | 全部判定测试直接报错 | 补齐 `midi` / `pitch_class` / `cents` 派生属性 |
| 2 | **低置信度检测结果仍被标记为"有效"** | 实测 10dB 噪声下把 B3 读成 83.07Hz（音名 E），置信度仅 0.49——若进入判定就是**冤判** | 新增 `accepted` 字段，`valid` 同时要求 accepted；低置信度读数只保留作诊断 |
| 3 | 备份文件名只精确到秒 | 同一秒内"会话结束备份 + 手动备份"会互相覆盖，**静默丢备份** | 文件名加毫秒 + 序号兜底 |

第 2 条尤其关键：它正是需求里"宁可慢一点，不可冤判"要防的东西，而它藏在
`PitchResult.valid` 的语义里——只有测试能发现。

## 4. 打包验证（M1 最高风险项，已通过）

| 项 | 结果 |
|---|---|
| PyInstaller 单文件夹模式 | ✅ 成功 |
| 产物体积 | **154.6 MB**（预算 ≤300MB，余量充足） |
| 打包耗时 | 66.7 s |
| **PortAudio DLL 是否打入** | ✅ `_internal/_sounddevice_data/portaudio-binaries/libportaudio64bit.dll` |
| 产物离屏自检 | ✅ 退出码 0 |
| 中英文语言包 | ✅ `_internal/i18n/{zh_CN,en_US}.json` |

**过程中的一个关键教训**：`--windowed` 产物没有标准输出，因此"退出码 0"
并不能证明音频链路可用——导入失败也被 `collect_diagnostics` 吞掉了。
为此把自检改造为：

1. 结果写入 `<程序目录>/logs/selftest.json`（构建脚本读取并打印）；
2. 音频后端不可用时**退出码 3**（打包事故），Qt 启动失败时退出码 4；
3. 设备枚举数量进报告——枚举本身就要调用 PortAudio（`Pa_GetDeviceCount`），
   所以"枚举到 22 个设备"即为 PortAudio 在打包产物中真正可用的证据。
