## 1. 新录音说明了什么

| 指标 | 旧麦克风（2026-10-07） | 新麦克风 + 已调音（2026-10-10） |
|---|---|---|
| 六根弦识别 | 全部识别 | 全部识别 |
| 音分偏差 | −38 ~ −93（琴没调准） | **−16 ~ +1** |
| 低音弦基频相对电平 | 比高音弦低约 30 dB | 基频 −19.5 dB（相对该段最强峰） |
| 18 次拨弦的归类 | — | **18/18 正确** |

**结论：琴与麦克风都到位了，低音弦不再是问题。**但复核过程中发现了一个**由旧环境引入、在新环境下有害**的问题。

## 2. 找到的问题：固定纠正会**改错正确的读数**

用程序真实链路（两级分析窗口 + 谐波校验）跑新录音，第 18 次拨弦（第 1 弦 E4）：

```
校正后：164.57 Hz → E3   （低了整整一个八度，误差 1200 音分）
不校正：329.14 Hz → E4   （正确）
```

**根因**：`harmonic_correct` 的低频分支（`hz <= 420Hz`，把 E4 的 329Hz 也算进去）
判据是"候选基频处存在谱峰即可向下修正"。而验证代码是：

```python
second = peak_at(candidate * 2.0)   # candidate = hz / divisor
```

当 `divisor == 2` 时，`candidate * 2` **恰好就是当前读数 hz 本身**——
这条"二次谐波支持"是**自我满足**的，等于没验证。旧麦克风下它有用（基频弱到 1/18），
换成正常麦克风后，琴箱共振/房间低频在 hz/2 处留下能量，于是把正确读数砍半。

## 3. 为什么不是"再调一个更好的阈值"

我把三类信号的真实频谱摆在一起量过：

| 场景 | 候选/读数 | 候选/频带中位 | 候选的独立谐波 |
|---|---|---|---|
| 真锁定：弱基频 E2 被读成 E3 | 2.6% | 7.3× | 2.7× |
| 真锁定：弱基频 A2 被读成 D#4 | 5.3% | 13.0× | ~0 |
| **误纠正：真实 E4 被砍成 E3** | **17~20%** | **7~9×** | 1.1~1.3× |

误纠正场景的"低八度成分"反而**更强**。**任何基于"存在性/强度"的单帧判据都会把两者混为一谈。**
我一度改成"要求一个独立于当前读数的谐波支持"，它能挡住误纠正，但也挡掉了真实的十二度锁定
（合成信号里只含 3 的倍数次谐波）——**用一个只有单个反例、无法充分验证的新规则去替换旧规则，
是在制造新的不确定性，而不是解决问题**。

## 4. 采用的方案：配置化 + 用先验消解歧义 + 不符预期就提示

### 4.1 谐波校验变成可选策略

`YinConfig.harmonic_mode` / `AnalyzerConfig.harmonic_mode`：

| 模式 | 行为 | 适用 |
|---|---|---|
| `off` | 不做任何频谱纠正 | 已知环境干净 |
| **`auto`（默认）** | 只保留高频区保守规则 | 正常麦克风 |
| `presence` | 额外启用低频"存在性"规则 | 低频响应差的设备（旧环境） |

`presence` 的价值没有被丢弃：它作为**可选补偿**保留，由配置档案按实测决定是否启用。

### 4.2 乐器配置档案（`core/instrument.py`）

一份 JSON，描述"这把琴 + 这套录音环境"：

```
data/instruments/我的吉他.json
├─ strings[]      每根弦：目标音高、实测频率、音分偏差、电平、置信度
├─ detection      谐波校验模式、频率范围、置信度下限、低频增强开关、判定容差
├─ max_fret       最高品（决定"可弹音集"）
├─ reference_a4_hz / created_at / notes
```

支持调弦预设（标准 / Drop D / 降半音 / 降全音 / Open G / DADGAD），
也可完全由实测生成。**目标音高始终记标准值**，实测偏差单独记录——
否则"琴没调准"会被当成"新调弦"固化下来。

### 4.3 用先验消解八度歧义，而不是猜频谱

```python
resolve_hz(329.14, profile)                  # → E4, -2.6 音分, exact
resolve_hz(164.57, profile, expect_midi=64)  # → E4, -2.6 音分, octave_adjusted
resolve_hz(110.0,  profile, expect_midi=64)  # → unexplained（弹的是 5 弦，不能算成 1 弦准了）
```

优先级是刻意设计的：**先相信原读数**，只有解释不通时才尝试谐波关系。
早期实现直接在"原读数 + 各种谐波"里挑偏差最小的，结果会把一个本来正确的
164.57Hz（E3，偏差 2.6 音分）乘 3 解释成 B4（偏差 0.6 音分）——
**为了让数字好看而把音改错**。

`expect_midi` 只接受"检测值偏高"（YIN 锁到高次谐波的已知失效模式），
**不接受"检测值只有预期音的一半/三分之一"**：那更像弹错了弦
（调第 1 弦时弹响第 5 弦，110×3 恰好落在 E4 附近），硬算成"准的"就是在骗用户。

### 4.4 发现不符预期就提示用户（需求第 1 点）

`check_measurements()` 给出**可执行**的提示：

| 代码 | 触发 | 提示 |
|---|---|---|
| `out_of_tune` | 某弦偏差 ≥ 20 音分 | "第6弦偏低 15 音分 → 建议先调音" |
| `missing_strings` | 某弦没测到 | 列出漏测的弦 |
| `level_imbalance` | 某弦比最强弦低 ≥ 12 dB | "试着把麦克风靠近音孔或换位置" |
| `different_tuning` | 各弦都差 ≥ 60 音分 | "看起来不是当前配置的调弦 → 新建对应调弦的档案" |
| `unexplained_pitch` | 实时检测不属于本琴可弹音 | 提示检查麦克风摆位/增益 |

实时路径也接上了：练习中连续 3 次检测到"本琴解释不通"的音高，
界面直接给出提示，而不是默默按某个猜测处理。

## 6. 保留的旧行为

M1 的 `presence` 规则与它的真实录音固件**全部保留**，只是改成显式选择：

- `tests/test_real_recording.py` / `test_low_frequency.py` 用 `LEGACY_DETECTOR`
  或 `harmonic_mode="presence"` 明确声明"这些固件来自低频极差的麦克风"；
- 新增固件 `real_new_mic_e4.wav` 与回归测试，钉住"默认模式不得砍半"。

**这样两套环境各自被测试覆盖**，而不是用一个阈值去讨好两边。
