## 3. 关于音频设备的结论（选购麦克风参考）

### 3.1 实测结论

| 设备 | 实测结果 |
|---|---|
| 蓝牙音箱麦克风（Beosound A1 等） | **不可用**：150 秒录音里只有 9 秒有信号，94 秒是数字静音（VAD 开闸行为） |
| 内置阵列麦克风（Realtek 等） | 中高音弦正常；**最低两根弦（E2 82Hz、A2 110Hz）电平低约 30dB**，E2 经常测不到 |
| USB 声卡（用户当前配置） | 未向 Windows 暴露可用录音端点；探测不到 |

### 3.2 选购要点

- **需要 60–150Hz 有良好响应**：这是能否稳定识别第 6、5 弦的关键（E2 = 82.41Hz）
- **避免蓝牙麦克风**：存在 VAD 开闸、采样率低（免提模式常为 8–16kHz）等问题
- 推荐方向：USB 电容麦克风（心形指向）或吉他音频接口（线路输入几乎无噪声）
- 采样率 44.1k 或 48k 都可以（程序会协商并写回设置）；单声道足够
- 麦克风离吉他 20–30cm，避开正对音孔（音孔低频过强反而容易糊）

### 3.3 一个好消息：低音弦限制不影响核心练习

判定只认音名，而 E2 的二次谐波是 E3——**音名相同**，所以即使低频段锁到高八度，练习判定结果仍然正确。
受影响的只有调音器的八度显示（已用显示平滑缓解）与实时音高表的观感。

## 4. 本机环境约束（恢复时必读）

这些是排查出来的、会在下次继续咬人的坑：

1. **pip 不可用**：本机 Windows 权限模型下，`os.mkdir(path, 0o700)` 与 `tempfile.mkdtemp()`
   创建的目录 ACL 损坏、无法读写（`icacls` 也无法处理），而 pip 内部正是用 `mkdtemp` 解包。
   → 依赖改为**解包官方 wheel 到 `.vendor/`**（已被 `.gitignore` 排除）。
2. **pytest 临时目录**：pytest 自带 basetemp 机制同样创建 0o700 目录并在会话结束时清理，
   在本机会让整个测试会话崩溃 → `conftest.py` **接管了 `tmp_path` 夹具**，固定到 `.tmp/tests/`。
3. **`src/jitatrainer/compat.py`** 在运行期探测并修补 `tempfile.mkdtemp`；`run.py` 与 `conftest.py`
   会把 `.vendor` 与 `src` 加入 `sys.path`。
4. **PowerShell 的 schannel TLS 不可用**（`curl`/`Invoke-RestMethod` 报 `SEC_E_NO_CREDENTIALS`），
   但 Python 自带 OpenSSL 正常 → 所有 HTTP 调用统一走 Python。
5. **GitHub 直连不稳定**：`sync_github.py` 会自动探测本地代理（本机为 `127.0.0.1:7897`）并重试 3 次。
6. **凭据**：访问令牌在 `.secrets/github_token.txt`（已被 `.gitignore` 排除，**永不提交、永不打印**）。
7. 遗留：`.tmp/pytest`、`.tmp/pytest-work` 两个目录在早期崩溃时被写坏，无法删除，已被 git 忽略。
